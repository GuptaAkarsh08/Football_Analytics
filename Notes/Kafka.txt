Kafka - Its a place where topics are stored and saved. It is run through Zookeeper

Terminologies:- 

1.1 — Topic

A topic is a category/folder where messages are stored. Think of it like a WhatsApp group — raw.matches is one group where all match data goes, raw.players is another group for player data. Producers send messages to a specific group, consumers read from that group.

1.2 — Broker

A broker isdocker exec kafka kafka-topics --list \
  --bootstrap-server localhost:9092 a Kafka server that stores the data. Right now you have 1 broker (KAFKA_BROKER_ID: 1). Netflix might have 100+ brokers. Think of brokers as hard drives — more brokers = more storage and more capacity to handle traffic. Each broker holds some portion of the topics.

1.3 — Leader

When a topic has copies across multiple brokers (for safety), one broker is the "leader" for that topic. All reads and writes go through the leader. The others are "followers" — they just keep backup copies. If the leader dies, a follower gets promoted to leader automatically. Since we have only 1 broker, it's the leader for everything.

A quick note for your notes too:

1.4 — Partition

A topic is split into partitions. Think of it like lanes on a highway — more lanes = more cars can move simultaneously. raw.matches might have 3 partitions so 3 consumers can read in parallel. Messages with the same key (like team_id) always go to the same partition, keeping them in order.



Commands To Run Kafka-

(Command) Create a topic - docker exec kafka kafka-topics --create \
                        --topic raw.matches \
                        --bootstrap-server localhost:9092 \
                        --partitions 3 \
                        --replication-factor 1


(Command) Check Existence of the topic - docker exec Kafka kafka-topics --list\
                                         --bootstrap-server localhost:9092

(Command) Send a Message and read it block - docker exec -it kafka kafka-console-producer --topic raw.matches --bootstrap-server localhost:9092

Test 1 — Consumed from non-existent topic
Result: UNKNOWN_TOPIC_OR_PARTITION, retried continuously
Why: KAFKA_AUTO_CREATE_TOPICS_ENABLE=false — prevents silent typo-topics in production

Test 2 — Consumer without --from-beginning
Result: only shows NEW messages, ignores old ones already in the topic
Why: offset determines where a consumer starts reading, not whether data exists

Test 3 (unplanned) — Retention expiry
Result: messages from Aug 31 disappeared by Sep 10 (10 days later)
Why: Kafka default retention = 7 days, auto-deletes old messages regardless of read status

Test 4 — Stop/restart Kafka container
Result: first attempt failed (TimeoutException) — Kafka wasn't ready yet after docker start
Fix: added sleep before reconnecting
Why: "container running" ≠ "service ready" — same problem Airflow sensors solve

Kafka concepts (pizza analogy):
- Partition = zone splitting a topic for parallel processing
- Replication Factor = backup stores per zone (durability)
- Leader = the one store actively serving a partition right now
- Replicas = leader + all backup copies
- Isr = backups that are fully caught up, safe to promote
- __consumer_offsets = shared tracker of what each consumer has read so far
